# ระบบจับฉลากแบ่งสายฟุตบอล 7 คน วันรพี 69 — v1.9

## บันทึกวิดีโอทั้งจอลงคอมโดยตรง

ใช้ Chrome หรือ Microsoft Edge บน Windows ที่เปิดระบบผ่าน GitHub Pages หรือ `localhost`:

1. กด **เริ่มบันทึกวิดีโอ** แล้วเลือกโฟลเดอร์เก็บงานในหน้าต่าง Windows (เลือกครั้งเดียวต่อรอบ)
2. กดเริ่มบันทึกอีกครั้ง แล้วเลือก **ทั้งหน้าจอ** ที่เปิด Google Meet และเลือกแชร์เสียงระบบเมื่อมี
3. เลือกความละเอียด `1280 × 720` สำหรับ Meet ชัด หรือ `960 × 540` สำหรับประหยัดพื้นที่

ระบบเขียนไฟล์ WebM ตรงลงโฟลเดอร์ที่เลือก แบ่งไฟล์อัตโนมัติทุก 10 นาที และเก็บภาพ PNG กับไฟล์สำรอง JSON ลงโฟลเดอร์เดียวกัน โดยไม่กระทบการนำเสนอใน Meet

## ใช้งานวันงาน

1. เปิด `เปิดระบบ_Windows.bat` แล้วรอให้เบราว์เซอร์เปิดเอง
2. เปิดหน้าควบคุม และกด **เปิดหน้าจอนำเสนอ**
3. ดูรายการ **ตรวจความพร้อมก่อนเริ่ม** ให้ครบทั้ง 4 ข้อก่อนเริ่มถ่ายทอดสด
4. แชร์เฉพาะหน้าจอนำเสนอใน Google Meet
5. หากใช้ควบคุมด้วยมือถือ ให้กด **เริ่ม / แสดง QR ควบคุมมือถือ** ใน `control.html` แล้วสแกน QR เพียงครั้งเดียว

หน้าควบคุมจะแสดงสถานะ “จอนำเสนอเชื่อมต่อแล้ว” ต่อเมื่อได้รับสัญญาณจากหน้าจอนำเสนอจริงภายใน 5 วินาที

## การซ้อมและถ่ายทอดสด

การสลับโหมดจะล้างผลปัจจุบันทุกครั้งโดยตั้งใจ เพื่อไม่ให้ผลซ้อมติดออกอากาศ โหมดถ่ายทอดสดจึงเริ่มจากข้อมูลว่างเสมอ

การล็อกผลเป็นเพียงตัวกันกดพลาด ไม่ใช่ระบบรักษาความปลอดภัย การปลดล็อกต้องพิมพ์คำว่า `ปลดล็อก` และไม่มีรหัสลับอยู่ในไฟล์สาธารณะ

## ควบคุมด้วยมือถือแบบ QR (Apps Script — แนะนำสำหรับงานนี้)

เวอร์ชัน 1.8 แยกส่วน “ตั้งค่าก่อนเริ่ม” ออกจากส่วน “หน้าจอที่กำลังออกอากาศ” ให้เห็นลำดับการทำงานชัดเจนขึ้น หน้าควบคุมรองรับมือถือทั้งแนวตั้งและแนวนอน และหน้าจอนำเสนอปรับขนาดข้อความตามพื้นที่อย่างต่อเนื่อง โดยคงหน้า `mobile-control.html` และการควบคุมเดิมไว้ทั้งหมด

ตั้งค่า Apps Script หนึ่งครั้งตาม `APPS_SCRIPT_QR_SETUP_TH.md` จากนั้นกดปุ่มเริ่ม QR ที่หน้าควบคุม ระบบจะจำรหัสรอบไว้ในคอมและคง QR เดิมจนกว่าจะกดสร้างรอบใหม่

- คอมพิวเตอร์: `control.html` และ `display.html`
- โทรศัพท์: `mobile-control.html`

หากมือถือจอดับหรือไม่ได้ใช้งานเกิน 3 นาที **ไม่ต้องสร้าง QR ใหม่**: ปลุกหน้าจอแล้วกลับมาที่แท็บเดิม ระบบจะเชื่อมต่อใหม่เอง; หากเบราว์เซอร์ถูกปิด ให้สแกน QR เดิมที่คอมยังแสดงอยู่

หน้าควบคุมจะแสดงสถานะ `รอมือถือสแกน QR`, `มือถือเชื่อมต่อแล้ว`, หรือ `มือถือพักหน้าจอ` โดยสถานะพักหน้าจอไม่ทำให้รอบควบคุมหมดอายุ

## Firebase (ทางเลือก)

หากต้องการการซิงก์ที่เร็วกว่า Apps Script สามารถใช้ Firebase ได้ตาม `FIREBASE_MOBILE_SETUP_TH.md` แต่หากกรอก Firebase ครบ ระบบจะพักการซิงก์ Apps Script อัตโนมัติ เพื่อไม่ให้มีสองแหล่งข้อมูลแข่งขันกัน

## ซิงก์คนละเครื่องแบบเดิม (Google Apps Script)

ค่าเริ่มต้นซิงก์ได้เฉพาะแท็บ/เบราว์เซอร์ในเครื่องเดียวกัน หากหน้าควบคุมและหน้าจอนำเสนออยู่คนละเครื่อง ให้ทำครั้งเดียวก่อนงาน:

1. สร้างโปรเจ็กต์ที่ [Google Apps Script](https://script.google.com/) แล้ววางเนื้อหาจาก `GAS_BACKEND.gs`
2. Deploy เป็น **Web app** โดยอนุญาตให้ผู้ใช้งานตามที่หน่วยงานกำหนด (ต้องให้เครื่องหน้าควบคุมและจอนำเสนอเรียก URL นี้ได้)
3. คัดลอก URL ที่ลงท้ายด้วย `/exec` ไปใส่ใน `sync-config.js`
4. อัปโหลดไฟล์ทั้งหมดไปยัง GitHub Pages ใหม่ แล้วเปิดทั้งสองเครื่องจาก URL เดียวกัน

บริการนี้เก็บเฉพาะสถานะการจับฉลากและสัญญาณว่าจอนำเสนอยังเปิดอยู่ จึงควรจำกัดสิทธิ์การเข้าถึงของ Web app ให้เหมาะกับงาน

หากไม่กรอก Firebase ระบบเดิมยังทำงานตามปกติ: เปิดในเบราว์เซอร์/เครื่องเดียวกันได้ทันที หรือใช้ Apps Script ตามขั้นตอนข้างต้นสำหรับหลายเครื่อง

## ส่งออกผล

- **พิมพ์ / บันทึก PDF**: เปิดหน้าสรุปโดยเฉพาะ ไม่ขึ้นกับหน้าที่กำลังออกอากาศ
- **บันทึกสรุปเป็น PNG**: ดาวน์โหลดภาพสรุปสำหรับส่งในกลุ่มทันที (ต้องเชื่อมอินเทอร์เน็ตเพื่อโหลดตัวช่วยครั้งแรก)
- **ดาวน์โหลดไฟล์สำรอง JSON**: เก็บสำรองสถานะดิบ

บนหน้าจอนำเสนอกด `1`–`5` เพื่อเปลี่ยนหน้า และกด `F` เพื่อเต็มจอ
